每周计划详情（W1 — W12）
W1　6/8 — 6/13
第一周（本周）
🎯 梳理启动 + 保险模块沟通
  • 系统全流程 & 审批节点梳理（启动）——以V2.1说明书为底，逐模块拆解所有流程和审批签字节点系统
  • 保险模块梳理（沟通）——联系季嘉莉、沈明明、黄欢欢，收集险种、承保机构、保额、覆盖人员信息沟通
  • 组织架构图更新（制作）——参考以往架构图，融入近期变动内容
  • 大框架细节模块确认（拆解）——将V2.1六大模块拆解为子模块，列出待确认问题系统
W2　6/15 — 6/20
第二周
🎯 签字流程设计 + 入职培训PPT + 保险确认
  • 系统全流程梳理（深入）——补充遗漏节点，与Jenny/Bella确认审批链路系统
  • 签字流程设计——设计线上签字→盖章全链路，确定前置审批节点和流转逻辑优先
  • 保险模块梳理（确认）——汇总沟通结果，确认保险模块需求沟通
  • 入职培训PPT更新——更新内容框架、完成制作，整体定稿内容
  • 大框架细节模块确认（深入）——逐模块确认字段、权限、流转规则系统
W3　6/22 — 6/27
第三周
🎯 签字流程开发 + 系统搭建启动 + 员工手册对接
  • 签字流程开发——基于设计方案，开发线上签字确认功能，审批→签字→用印全链路优先
  • 人事系统搭建（基础架构）——数据库表设计、RLS权限策略、Storage配置、前端框架系统
  • 员工手册优化（对接安子玥）——收集优化意见和修改需求沟通
  • 职位管理整理（启动收集）——开始收集每位在职员工职能分工信息数据
  • 档案电子化（启动扫描）——开始分批获取纸质档案扫描件档案
W4　6/29 — 7/4
第四周
🎯 签字流程联调 + 招聘入职模块开发
  • 系统全流程梳理（补全确认）——最终确认所有模块流程和审批节点，形成完整流程图系统
  • 签字流程联调测试——全链路联调，确保审批→签字→用印跑通优先
  • 人事系统搭建（招聘+入职模块）——开发招聘管理、入职管理核心模块系统
  • 员工手册优化（收集反馈）——汇总安子玥反馈，整理修改清单沟通
  • 档案电子化（持续扫描）——继续分批扫描档案
W5　7/6 — 7/11
第五周
🎯 在职管理模块 + 手册定稿 + 职位管理确认
  • 人事系统搭建（在职管理模块）——试用期、转正、合同续签、调岗调薪系统
  • 员工手册优化（修改定稿）——完成修改，形成终版内容
  • 职位管理整理（确认）——逐部门确认职能分工信息数据
  • 档案电子化（持续扫描）——继续分批扫描档案
W6　7/13 — 7/18
第六周
🎯 日常+离职模块开发
  • 人事系统搭建（日常管理模块）——钉钉假期、请假、排班、发薪系统
  • 人事系统搭建（离职管理模块）——离职申请、交接清单、社保减员系统
  • 档案电子化（持续扫描）——继续分批扫描档案
W7　7/20 — 7/25
第七周
🎯 保险退休模块 + 权限表单
  • 人事系统搭建（保险+退休模块）——保险管理、退休管理，数据来自W1-W2梳理成果系统
  • 人事系统搭建（权限体系）——角色权限、RLS策略、薪资隔离系统
  • 档案电子化（系统导入启动）——将已扫描档案批量导入系统档案
W8　7/27 — 8/1
第八周
🎯 表单电子化 + 外部集成
  • 人事系统搭建（表单电子化）——全量表单清单、专属链接、PDF导出、归档存储系统
  • 人事系统搭建（外部集成）——钉钉考勤/假期/发薪、用印系统对接系统
  • 档案电子化（持续导入）——继续导入已扫描档案档案
W9　8/3 — 8/8
第九周
🎯 系统收尾 + 自测启动
  • 人事系统搭建（收尾完善）——修复开发中遗留问题，补全边界条件和异常处理系统
  • 档案电子化（核对）——核对已导入档案与系统记录的一致性档案
  • 系统自测启动——已完成的核心功能开始自测，记录Bug测试
W10　8/10 — 8/15
第十周
🎯 全面测试
  • 系统全面测试——全模块功能测试、流程跑通、权限验证、边界条件测试测试
  • 签字盖章流程全链路验证——端到端跑通审批→签字→用印全流程测试
  • 档案导入收尾——确认所有档案已导入系统档案
W11　8/17 — 8/22
第十一周
🎯 Bug修复 + 回归验证
  • Bug修复（第一批）——修复测试阶段发现的Bug，优先处理阻断性问题测试
  • 回归测试——已修复功能回归验证测试
W12　8/24 — 8/31
第十二周
🎯 最终验收 + 上架交付
  • Bug修复（第二批）+ 回归验证——修复剩余Bug，全面回归测试
  • 用户验收准备——数据迁移、权限配置、用户操作手册系统
  • 系统上架 🎯——最终数据迁移、权限配置、用户验收，确认系统可正常使用交付
  • 上线后观察——监控系统运行状态，快速响应问题运维
